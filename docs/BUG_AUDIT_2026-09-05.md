# MediKiosk bug audit — 5 September 2026

Status: review complete; fixes awaiting the owner's approval. No application fixes were made.

## Scope and evidence

Reviewed every active frontend component, shared audio code, CSS, backend endpoint and helper, clinical schema, launch scripts, and smoke suite. Baseline: commit `b0e3b76` plus the pre-existing uncommitted changes. Backup copies are not active application code.

- Production frontend build: **PASS** (`npm run build`, 43 modules).
- Existing smoke suite: **24/24 PASS**, with real llama3.1:8b, EasyOCR, faster-whisper, English Piper, and Hindi Piper.
- Additional isolated API/function probes reproduced failures not covered by that suite: schema violations, string-boolean coercion, missing interview cap, empty-message acceptance, missing emergency alerts during AI failure, unsafe merging, rule errors, unrestricted endpoints, invalid-phone acceptance, nonexistent-session export, malformed-history export failure, and lost lab metadata.
- Browser checks reproduced direct interview access without onboarding, sample-summary fallback, continued lookup after three failures, and a temporary unavailable screen while OCR was running.
- Servers were initially stopped; Ollama was running. Testing used a separate temporary SQLite database and separate in-memory sessions. The audit did not use the real patient database for registrations or updates.
- The isolated loader skipped only the module-level database initialization call, then initialized the unchanged database helper against the temporary database. The live smoke run used the unchanged application logic and real model services. Fault-injection probes replaced only the AI response/service behavior in a separate process.

Evidence labels: **Tested** = reproduced through browser, API, or isolated function execution; **Code** = a concrete defect established by the current control/data flow, but its full end-to-end trigger was not executed.

P1 = high priority: privacy, incorrect/lost clinical information, unavailable essential functions. P2 = normal priority: broken flows, misleading indicators, reliability or accessibility defects. These are engineering priorities, not a medical validation of the clinical rules.

## Privacy, access, and session isolation

| B02 | P1 / Code | **Staff access survives patient reset and idle timeout.** `clearSession()` resets patient state but never calls `setStaffAuthenticated(false)`. | B03 | P1 / Code | **“Clear everything” does not erase everything entered.** The handler performs no backend request. | B04 | P1 / Code | **Previous patient's spoken summary can be replayed after reset.** `lastSpokenBlob` is module-global and never cleared. | B08 | P1 / Code | **Patient database is tracked by Git.** `git ls-files backend/medikiosk.db` returns the real registry file; it is already modified locally. Removing already-tracked data/history needs a separately reviewed plan; no history rewrite was attempted. |

## Interview correctness and emergency alerts

| ID | Priority / evidence | Bug and reproduction / impact | Location and proposed fix |
|---|---|---|---|
| B09 | P1 / Tested | **Deterministic emergency alerting waits for AI success.** With `_call_ollama` returning a simulated 503, `chest pain and breathlessness` returns 503 and creates no nurse alert. The rule check runs only after inference/JSON parsing; slow inference also delays alerts. | `backend/main.py:802-888`. Evaluate and record deterministic alerts before the AI call, and preserve them if inference fails. |
| B10 | P1 / Tested + Code | **Keyword safety net has both false positives and false negatives.** `My chest is fine and my breathing is normal.` returns true. `I am not sure why I have chest pain and breathlessness.` returns false because “not” negates the entire prefix. A Hindi equivalent of chest pain with breathing difficulty returns false. Rules inspect only the latest message, so symptoms split across turns are not combined by this safety net. AI may catch some cases, but cannot repair its independence. | `backend/main.py:560-629`. Improve symptom/negation boundaries, support Hindi and session-level symptom context, and test a clinician-reviewed rule corpus. |
| B11 | P1 / Tested | **AI responses are not actually schema-validated.** A probe returned `hpi.severity={bad:'type'}` and an unexpected field; `/chat` returned 200 unchanged. A reply object also passes. `red_flag:'false'` becomes true through Python `bool()`, and `interview_complete:'false'` remains a truthy string in React. Missing required metadata is not filled or enforced. | `backend/main.py:673-711`, `:850-888`; `frontend/src/App.jsx:211-242`; `docs/schema.json`. Define validated request/response and clinical-data models, reject/repair malformed inference, and set trusted metadata server-side. |
| B12 | P1 / Tested | **Merging locks in wrong answers and contradictory history.** Merging onset `unknown` → `yesterday` and severity `2/10` → `8/10` leaves the original values. Allergies `['none']` plus `['penicillin']` produces both. Existing nonempty scalars cannot be corrected; arrays only append. | `backend/main.py:715-742`. Distinguish unknown from known, support explicit corrections and resolved contradictions, and retain meaningful provenance. |
| B13 | P2 / Tested + Code | **The advertised 15–20 exchange cap is prompt-only.** A request with 20 prior user answers and a model response saying incomplete remains incomplete on the 21st turn. The UI also continues enabling chat after completion, while its saved summary can become stale if a later response says incomplete. | `backend/main.py:802`; `frontend/src/App.jsx:217`, `:449-471`. Count successful turns server-side, enforce completion, and define whether post-completion correction is allowed. |
| B14 | P1 / Tested + Code | **Deterministic question scheduling conflicts with the interview requirements.** After an AYUSH chief complaint, the generated mandatory next instruction asks location, not Agni/Vikriti. It is computed before extracting the latest answer, so it can demand the field just answered. The schedule omits radiation, medications/allergies, past/family/personal history, and Prakriti, then says required history is sufficiently covered. Model discretion is the only remaining coverage for several fields. | `backend/main.py:746-798`, `:813-824`. Base the next question on the updated information, implement the documented AYUSH order, and track the required history fields explicitly. |
| B15 | P2 / Tested + Code | **Empty input and arbitrary history/context are accepted.** Whitespace-only `message` returns 200 with injected valid AI output. History allows arbitrary string dictionaries, including client-supplied system roles; department is any string. The backend trusts client history and identity context. | `backend/main.py:156-164`, `:802-824`. Validate nonblank text, bounded history, permitted roles/departments, and use authoritative session identity/history. |
| B16 | P2 / Code | **Red-flag data differs between the same response and stored session.** `result['data']` is copied before the deterministic flag/reason is written into accumulated data. The top-level response can say true while its clinical `data` omits the flag. Nurse alerts also discard rule/AI provenance, and overwrite the reason for repeated alerts. | `backend/main.py:852-888`, `:891-917`. Build the returned snapshot after all updates and retain alert provenance/events. |

## Important limits and next verification

This is a broad engineering audit, not a guarantee that no undiscovered bugs remain. Specific limits:

- No physical microphone/camera interaction, touchscreen/OS kiosk escape testing, listening-based Hindi pronunciation assessment, or full range of phone sizes was performed.
- Real model smoke coverage used the existing short conversations and synthetic prescription/tone. It does not establish clinical safety, multilingual accuracy, extraction accuracy over diverse documents, or robustness against adversarial prompts.
- No independent FHIR/ABDM conformance validation, package vulnerability database scan, sustained load test, or real hospital integration was performed. The mock integration is an intentional limitation, not itself counted as a bug.
- Automatic approval review rejected the browser's **Yes, clear everything** action because inspection authorization did not include potentially destructive clinical-data deletion. No workaround or indirect reset was attempted after the rejection. The dialog was dismissed. Reset-related findings are labeled Code.
- Existing uncommitted application/database changes and backup files belong to the owner and were left intact.

Recommended approval order: B01–B12 and B17–B24 first (access, session isolation, alerting, clinical correctness, record availability), then the remaining broken flows and reliability fixes. Clinical keyword changes need explicit expected cases and review, not just broader substring matching. Database retention/deletion and any tracked-history removal should be reviewed as concrete plans before destructive actions.

After approval, implement fixes in small groups with regression checks, exercise the complete English and Hindi journeys, and update this report with resolved IDs and remaining limitations.
